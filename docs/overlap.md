# Overlap 调度：双节拍

## 问题

主循环若让 CPU 等 GPU——每步算完、拷回、处理、再入队下一步——GPU 在 CPU 介入的整段
时间里空转。推理引擎对主循环的要求是：**计算不暂停**。

## 双节拍

把一拍循环拆成两个错开的节拍：**入队节拍**与**收货节拍**。CPU 每拍先把本拍的全部
工作（H2D、kernel、D2H）非阻塞地入队，然后阻塞等**上一拍**的 D2H 落地、收货写出：

```
CPU：  入队 t ── 等待 t-1 结果 · 收货 ── 入队 t+1 ── 等待 t 结果 · 收货 ── …
GPU：      ╰────── 算拍 t ──────╯       ╰────── 算拍 t+1 ──────╯
```

CPU 等待 t-1 结果的窗口，恰好是 GPU 计算拍 t 的窗口——等待没有被消灭，而是被搬进了
GPU 的工作时段。产出永远比消费早一拍：**节拍滞后一拍，就是 overlap 的全部**。

## 载体

三条 CUDA 流：主计算流只跑 kernel，H2D / D2H 各走一条独立拷贝流，与计算并行。跨流
交接靠 cudaEvent 接力，事件的方向即数据依赖的方向：h2d_done 告诉计算流输入到位，
compute_done 告诉拷贝流结果出炉，d2h_done 告诉主机可以收货。

滞后一拍还需要一个能容纳"已产出、未消费"的槽位：深度为 2 的结果缓冲 / 事件环
（ping-pong）。每拍 ①②③ 写本拍槽，④ 收上一拍槽，拍末翻转。事件随槽成对——
收旧与录新互不覆盖，这是不串拍的保证。

## 唯一阻塞点

全循环只有一处主机阻塞：④ 等上一拍的 d2h_done。它同时是节拍器——空等一整拍换 GPU
满拍计算，是设计而非事故。除它之外的一切（收 stdin、编码写出、入队）都不得引入同步。

## 对应

`scheduler.cpp` 的 run_loop 每拍五步即此节拍：⓪ 收消息 → ① async_h2d →
② async_forward → ③ async_d2h → ④ sync_recv（唯一阻塞点）。`cuda/cuda_engine.cpp`
是三流 + 事件环的实现。原型为 mini-sglang 的 overlap 调度；逐行研读笔记的历史
版本见 git（commit f7bf6e4）。
